# 阶段 1：首页 UI 与交互蓝图

记录日期：2026-05-25

## 1. 页面名称

高级公开首页

## 2. 页面目标

让访客第一眼建立信任，并知道这个网站可以继续探索哪些方向。

核心判断：

```text
这个人很懂 AI，也真的在一线做东西。
```

## 3. 用户主任务

访客进入首页后，快速完成三件事：

1. 判断网站定位。
2. 找到自己感兴趣的入口。
3. 产生继续探索或联系的意愿。

## 4. 信息优先级

### P0

- 强定位标题。
- 简短可信的说明文案。
- 知识库 / 工具 / 项目 / SOP 服务入口。
- 联系 / 咨询入口。

### P1

- 精选知识。
- 精选工具。
- 精选项目。
- 社交入口。
- 动态效果。

### P2

- 付费标记。
- 管理端入口。
- 监控能力。
- 更多内容列表。

## 6. 动效规则

### 必须克制

动效只服务高级感和探索感，不抢主文案。

### 可用动效

- 鼠标光晕跟随。
- 浅色粒子轻微聚合/扩散。
- 背景细网格缓慢漂移。
- 卡片 hover 浮起。
- 入口卡片轻微磁吸。
- 滚动进入时透明度和位移变化。

### 禁止动效

- 大面积黑色科技背景。
- 满屏重粒子。
- 复杂 3D 模型。
- 影响性能的连续高负载动画。
- 移动端必须手势操作才能理解页面。

## 7. 交互规则

- 点击知识库入口：进入 `/knowledge`。
- 点击工具入口：进入 `/tools`。
- 点击项目入口：进入 `/projects`。
- 点击 SOP 服务入口：进入 `/services`。
- 点击联系入口：后续可复制微信或跳转联系区，第一阶段可先滚动到联系区。
- 卡片 hover 展示轻量反馈，不改变信息结构。

## 8. 状态规则

### loading

第一阶段静态数据为主，不需要复杂 loading。

如果后续数据化，内容区显示骨架屏。

### empty

精选知识、工具、项目如果为空，展示“即将上线”占位，不显示空白区域。

### error

第一阶段无远程内容请求，暂不设计复杂错误页。

后续数据化后，内容区错误显示重试入口。

### submitting

第一阶段不做真实表单提交。

后续联系表单提交时，按钮进入 submitting，并禁止重复点击。

### success

后续联系/复制微信成功时显示轻量 toast。

### permissionDenied

公开首页无权限限制。

后续管理端入口如果出现，未登录时跳转登录页。

## 9. 组件映射

主组件库：

```text
shadcn/ui 风格组件 + Tailwind CSS
```

组件来源：

| 能力 | 组件 |
| --- | --- |
| 按钮 | Button |
| 卡片 | Card |
| 标签 | Badge |
| 输入/联系表单 | Input / Textarea，后续阶段 |
| 弹窗 | Dialog，后续阶段 |
| 通知 | Toast，后续阶段 |
| 动效 | 项目自定义组件 |

## 10. 开发注意事项

- 动效组件要独立封装，避免首页文件过大。
- 首页内容先用本地静态配置数组，方便后续接管理端。
- 所有入口路由先可访问，即使内容是占位。
- 移动端关闭或弱化鼠标跟随类动效。
- 不引入第二套 UI 组件库。

## 11. 验收清单

- 主任务明确。
- 首屏不是黑色主题。
- 第一屏有高级感和 AI 实践者可信度。
- 入口矩阵清楚。
- 动效存在但不影响阅读。
- 移动端基础可用。
- 没有超出第一阶段范围。

# 个人网站与 IP 自媒体产品 MVP PRD

## 1. 产品定位

这是一个公私分离的 AI 实践者个人网站。

登录前，它是个人名片、公开知识库、自研工具和服务入口；登录后，它是个人工作台、私人笔记库和后续工具宿主平台。

## 2. MVP 核心假设

如果网站能让本人持续记录真实 AI 实践，并把部分内容发布为公开文章，那么它可以逐步形成可信的个人数字据点，并为后续工具付费、知识付费和 SOP 企业服务打基础。

## 3. 目标用户

- 第一用户：本人，用于记录、管理知识和运行自研工具。
- 第二用户：从抖音、小红书或其他渠道进入的陌生访客，用于了解能力、阅读文章并建立信任。
- 后续用户：潜在企业客户，用于了解 SOP 服务和合作入口。

## 4. MVP 页面清单

| 页面 | 说明 | 优先级 |
| --- | --- | --- |
| 首页 | 能力名片、定位、能力卡片、最新文章入口 | 核心 |
| 公开知识库列表 | 已发布文章列表，按时间倒序 | 核心 |
| 公开文章详情 | 标题、日期、正文排版、返回入口 | 核心 |
| 登录页 | 单管理员账号密码登录 | 核心 |
| 私人工作台 | 登录后首页，展示统计和快捷入口 | 核心 |
| 私人笔记管理 | 笔记列表、状态、发布、撤回、删除 | 核心 |
| 私人笔记编辑器 | 新建和编辑笔记，保存为私密或发布 | 核心 |

## 5. MVP 功能范围

### 必做

- 首页能力名片。
- 公开知识库列表与文章详情。
- 单管理员登录鉴权。
- 私人笔记增删改查。
- 笔记默认私密。
- 笔记发布和撤回。
- 后台页面未登录时不可访问。
- 删除笔记二次确认。
- 基础响应式，移动端不跑版。

### 最小底座

- Next.js 全栈项目结构。
- PostgreSQL 数据模型。
- Prisma ORM。
- Auth.js / NextAuth.js 鉴权底座。
- `/tools` 路径预留。
- 内容状态字段：`DRAFT` / `PUBLISHED`。
- 创建时间、更新时间、发布时间字段。

### 不做

- 多用户系统。
- 评论、点赞、阅读统计。
- 标签、分类、搜索。
- 工具状态管理后台。
- 企业服务案例页。
- 移动端极致体验。
- 小程序。
- 公众号深度运营。
- 支付和知识付费。

## 6. 数据对象

### User

单管理员账号。

关键字段：

- `id`
- `name`
- `email`
- `passwordHash`
- `role`
- `createdAt`
- `updatedAt`

### Note

私人笔记和公开文章共用同一张表，通过状态区分。

关键字段：

- `id`
- `title`
- `slug`
- `excerpt`
- `content`
- `status`
- `createdAt`
- `updatedAt`
- `publishedAt`

## 7. 权限规则

- 访客只能访问首页、公开知识库列表、公开文章详情。
- 已登录管理员可以访问后台、查看所有笔记、编辑笔记、发布、撤回和删除。
- 后台页面、Server Actions、Route Handlers 都必须做服务端权限校验。
- 不能只依赖前端隐藏按钮来判断权限。

## 8. 验收标准

- 访客 3 秒内能看懂这个网站是谁的、做什么的。
- 公开文章列表和详情可正常访问。
- 未登录访问后台会被重定向到登录页。
- 登录失败有明确错误提示。
- 笔记可以新建、编辑、删除、发布和撤回。
- 删除操作有二次确认。
- 保存失败不能丢失用户输入。
- 移动端基础布局不崩。

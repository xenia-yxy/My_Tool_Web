# 阶段 2：内容发布闭环 Ne/Ti/Ni/Te 过程文档

记录日期：2026-05-25

## 文档定位

这份文档用于保存第二阶段从自由探索到可开发落地的关键判断。

它不是逐字聊天记录，而是阶段 2 PRD、UI 设计、开发计划和验收清单的上游依据。

阶段 1 已经完成公开首页 MVP，并在后续设计中加入了 `AI Practice` 品牌首屏和全站悬浮小助手。阶段 2 不继续扩大首页表现，而是回到 MVP 核心假设：

```text
本人能持续记录真实 AI 实践，并把部分内容发布为公开文章。
```

因此第二阶段的核心任务是打通“私人记录 -> 发布 -> 公开阅读”的最小内容闭环。

## 0. 第二阶段触发背景

阶段 1 解决的是公开门面：

- 访客第一眼知道这是一个个人 AI 实践者的数字据点。
- 首页能承接知识库、工具、项目、SOP 服务和联系入口。
- 首页视觉从通用模板感收束为 `AI Practice` 个人品牌。
- 悬浮小助手成为后续理解网站与知识库的创新入口。

但阶段 1 仍然没有验证内容系统本身：

- `/knowledge` 仍是占位。
- `/admin` 仍是占位。
- 还不能登录。
- 还不能新建、编辑、发布、撤回笔记。
- 还不能把私人笔记变成公开文章。

如果第二阶段继续做视觉、工具展示或 AI 小助手增强，项目会偏离 MVP 核心。第二阶段必须优先建立内容生产和发布能力。

## 1. Ne-A 自由探索

围绕第二阶段，先不急着写后台页面，而是重新打开问题：

```text
如果这个网站要真正变成个人 AI 实践者的数字据点，第二阶段最小但有效的一步是什么？
```

自然冒出的方向：

- 做登录，让站主能进入私人工作台。
- 做私人笔记库，让真实工作经验可以沉淀下来。
- 做公开知识库，让访客看到已发布文章，而不是占位页。
- 做文章详情页，让内容可以被阅读、分享、积累信任。
- 做发布和撤回，让同一条内容可以在私密和公开之间流动。
- 做删除二次确认，避免误删笔记。
- 做后台统计，让站主知道现在有多少私密笔记和公开文章。
- 做 Markdown 内容输入，先满足文字记录，不做复杂富文本。
- 做 slug，保证公开文章有稳定链接。
- 做服务端权限校验，不能只靠隐藏前端按钮。

也有一些容易膨胀的想法：

- 标签、分类、搜索。
- 富文本编辑器。
- 图片上传。
- AI 自动总结。
- 小助手接入知识库问答。
- 文章阅读统计。
- 评论、点赞、收藏。
- 多用户和会员。
- 知识付费。

这些方向有价值，但它们不是第二阶段的最小验证。

## 2. Ne-B 结构化整理

### 2.1 核心用户

第二阶段的第一用户是站主本人。

站主需要：

- 登录后台。
- 快速新建私人笔记。
- 编辑和保存笔记。
- 把合适的笔记发布成公开文章。
- 必要时撤回公开文章。
- 删除无用笔记。
- 在工作台看到内容状态概览。

第二用户是公开访客。

访客需要：

- 打开知识库列表。
- 看到已发布文章。
- 点击进入文章详情。
- 通过内容判断站主是否真实在做 AI 实践。

### 2.2 核心场景

场景 1：站主记录一条真实实践。

```text
登录 -> 新建笔记 -> 填写标题/摘要/正文 -> 保存为私密
```

场景 2：站主把一条笔记发布出去。

```text
进入笔记列表 -> 打开笔记 -> 点击发布 -> 文章出现在公开知识库
```

场景 3：站主修改公开文章。

```text
进入编辑页 -> 修改内容 -> 保存 -> 公开详情页更新
```

场景 4：站主撤回一篇文章。

```text
进入笔记列表或编辑页 -> 点击撤回 -> 文章从公开知识库消失
```

场景 5：访客阅读公开内容。

```text
首页/导航 -> 知识库 -> 文章详情 -> 返回知识库或联系
```

### 2.3 功能模块

第二阶段可以拆成六个模块：

1. 登录鉴权
   - 单管理员邮箱 + 密码登录。
   - 登录失败提示。
   - 后台路由保护。

2. 私人工作台
   - 展示笔记总数、私密数量、已发布数量。
   - 提供新建笔记、进入笔记列表、返回首页等快捷入口。

3. 笔记管理列表
   - 展示标题、状态、更新时间、发布时间。
   - 提供编辑、发布、撤回、删除入口。
   - 空状态提示。

4. 笔记编辑
   - 新建笔记。
   - 编辑已有笔记。
   - 字段包括标题、slug、摘要、正文、状态。
   - 保存失败不能丢失用户输入。

5. 公开知识库
   - 列出 `PUBLISHED` 笔记。
   - 按发布时间倒序。
   - 空状态不显示空白页。

6. 公开文章详情
   - 根据 slug 查询已发布文章。
   - 渲染标题、摘要、发布时间、正文。
   - 未发布或不存在时返回 404。

## 3. Ti 提纯

### 3.1 真实需求

第二阶段真正要验证的是内容闭环，而不是后台系统完整度。

必须满足：

- 能登录。
- 未登录不能进入后台。
- 能新建笔记。
- 能编辑笔记。
- 能删除笔记，并有二次确认。
- 能发布笔记。
- 能撤回文章。
- 公开知识库只显示已发布内容。
- 公开文章详情只允许访问已发布内容。
- 写操作必须服务端校验权限。

### 3.2 暂缓需求

暂缓：

- 标签、分类、搜索。
- 富文本编辑器。
- 图片上传。
- 文件管理。
- 阅读量统计。
- 评论和互动。
- AI 自动生成摘要。
- AI 小助手检索知识库。
- 多用户和角色系统。
- 付费和会员。
- 工具状态后台。

这些能力可以进入后续候选池，但不能进入第二阶段 P0。

### 3.3 技术约束

已有技术底座：

- Next.js App Router。
- Prisma + PostgreSQL。
- `User`、`Note`、`Account`、`Session`、`VerificationToken` 模型已存在。
- `NoteStatus` 当前为 `PRIVATE` / `PUBLISHED`。
- `.env` 已规划 `ADMIN_EMAIL`、`ADMIN_PASSWORD`、`AUTH_SECRET`、`AUTH_URL`。

重要判断：

- 第二阶段沿用现有 `PRIVATE` / `PUBLISHED`，不为了文档里的 `DRAFT` 改数据库枚举。
- 私密笔记等价于未发布草稿。
- 一个管理员足够，不做注册。
- 内容输入先用 textarea + Markdown，不引入复杂编辑器。
- 认证可以使用 NextAuth.js Credentials，但必须保证密码不明文落库。
- 关键写操作使用 Server Action 或 Route Handler，并在服务端二次校验管理员身份。

### 3.4 关键风险

风险 1：登录鉴权做得太重。

控制方式：

- 只做单管理员。
- 不做注册、不做找回密码、不做 OAuth。

风险 2：编辑器范围膨胀。

控制方式：

- 只做标题、slug、摘要、正文 textarea。
- 公开详情页用 `react-markdown` 渲染正文。

风险 3：公开文章和私人笔记边界混乱。

控制方式：

- 后台可以看到所有笔记。
- 公开区只查询 `status = PUBLISHED`。
- 未发布内容不允许通过 slug 访问。

风险 4：只做前端隐藏按钮，权限不可靠。

控制方式：

- 后台页面服务端校验。
- 所有写操作服务端校验。
- 发布、撤回、删除不能只依赖客户端状态。

## 4. Ni 收束

第二阶段主轴：

```text
打通单管理员内容发布闭环。
让站主能把真实 AI 实践记录为私人笔记，并把合适内容发布成公开知识库文章。
```

核心闭环：

```text
登录后台
  -> 新建/编辑私人笔记
  -> 发布为公开文章
  -> 访客在知识库阅读
  -> 内容建立信任
  -> 后续工具、项目、SOP 服务有内容支撑
```

阶段成功的标志不是后台功能多，而是：

```text
一条真实笔记可以从后台创建，并稳定出现在公开知识库和文章详情页。
```

## 5. Te 落地摘要

### 5.1 阶段名称

```text
阶段 2：单管理员内容发布闭环 MVP
```

### 5.2 P0 必做

登录鉴权：

- `/login` 登录页。
- 单管理员邮箱 + 密码登录。
- 登录失败有明确提示。
- 登录后进入 `/admin`。
- 未登录访问后台跳转 `/login`。

私人工作台：

- `/admin` 展示笔记总数、私密数量、已发布数量。
- 展示快捷入口：新建笔记、笔记管理、返回首页。

笔记管理：

- `/admin/notes` 笔记列表。
- `/admin/notes/new` 新建笔记。
- `/admin/notes/[id]` 编辑笔记。
- 支持保存标题、slug、摘要、正文。
- 支持发布、撤回、删除。
- 删除必须二次确认。

公开知识库：

- `/knowledge` 展示已发布文章列表。
- `/knowledge/[slug]` 展示已发布文章详情。
- 文章详情渲染 Markdown 正文。
- 没有已发布文章时显示空状态。

权限与安全：

- 后台页面必须服务端鉴权。
- 所有写操作必须服务端校验管理员身份。
- 密码不能明文存储。
- 公开区不能访问私密笔记。

### 5.3 P1 可做

- 保存成功/失败提示。
- slug 自动建议。
- 公开文章预览入口。
- 管理列表状态筛选：全部 / 私密 / 已发布。
- 编辑页显示最后更新时间。

### 5.4 P2 后置

- 标签、分类、搜索。
- 富文本编辑器。
- 图片上传。
- 文件附件。
- 文章阅读统计。
- AI 自动摘要。
- AI Practice Assistant 接入知识库检索。
- 知识付费和会员。
- 多用户。

### 5.5 数据对象

沿用现有模型：

```text
User
Note
```

`Note.status` 使用：

```text
PRIVATE   -> 私人笔记 / 未发布草稿
PUBLISHED -> 公开文章
```

发布时：

- `status` 改为 `PUBLISHED`。
- `publishedAt` 如果为空则写入当前时间。

撤回时：

- `status` 改为 `PRIVATE`。
- `publishedAt` 可以保留历史发布时间，也可以清空。

建议 MVP 阶段清空 `publishedAt`，避免公开列表排序含义混乱。

### 5.6 页面清单

| 路由 | 角色 | 说明 |
| --- | --- | --- |
| `/login` | 管理员 | 登录页 |
| `/admin` | 管理员 | 私人工作台 |
| `/admin/notes` | 管理员 | 笔记管理列表 |
| `/admin/notes/new` | 管理员 | 新建笔记 |
| `/admin/notes/[id]` | 管理员 | 编辑笔记 |
| `/knowledge` | 访客 | 已发布文章列表 |
| `/knowledge/[slug]` | 访客 | 已发布文章详情 |

### 5.7 验收标准

- 未登录访问 `/admin` 会跳转到 `/login`。
- 使用正确管理员账号密码可以登录。
- 使用错误密码登录失败，并显示明确提示。
- 登录后可以进入私人工作台。
- 可以新建一条私人笔记。
- 可以编辑并保存笔记。
- 可以发布笔记。
- 发布后文章出现在 `/knowledge`。
- 点击文章可以进入 `/knowledge/[slug]`。
- 撤回后文章不再出现在公开知识库。
- 删除笔记前有二次确认。
- 删除后后台列表不再显示该笔记。
- 公开区不能访问私密笔记。
- 移动端基础布局不崩。
- `pnpm lint` 通过。
- `pnpm build` 通过。

### 5.8 不做范围

第二阶段不做：

- 注册。
- 多用户。
- OAuth。
- 找回密码。
- 标签分类。
- 搜索。
- 评论互动。
- 阅读统计。
- 图片上传。
- 付费。
- AI 小助手真实知识库检索。
- 工具状态管理后台。

## 6. 后续能力候选池

第二阶段完成后，可以根据使用情况再进入下一轮产品化讨论。

候选方向：

- 知识库标签和分类。
- 搜索。
- AI Practice Assistant 接入已发布文章。
- 内容创作 SOP 模板。
- 工具项目真实详情页。
- SOP 服务案例页。
- 内容数据统计。
- 知识付费或工具付费。

这些能力必须基于第二阶段的真实使用反馈再决定，不能提前塞进阶段 2。

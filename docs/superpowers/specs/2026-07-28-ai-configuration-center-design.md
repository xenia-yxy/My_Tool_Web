# 技术方案：AI 配置中心

## 1. 背景和目标

系统将 AI Key 写在服务器环境变量中，维护者必须修改 `.env` 并重新部署才能替换供应商或模型。目标是让每个登录用户可在网站内添加、验证、启用、停用和删除自己的模型配置，使生图、图生图、识图和 Agent 直接使用该配置。

## 2. 范围和不做事项

本期保留现有按能力自动选模型的规则，不创建按每个页面单独绑定模型的复杂配置。支持 OpenAI、OpenAI 兼容、OpenRouter、Claude、Gemini、AIZHZO 和自定义兼容接口。联网搜索和 OSS 仍为系统服务配置，不开放为用户 API Key。

## 3. 架构和数据流

用户通过 `/account/models` 保存供应商、模型、Base URL、Key 和能力。Key 只在服务端以 AES-256-GCM 加密存入 `AiProviderCredential`，接口只返回脱敏预览。运行时按“用户已启用配置优先、服务器默认配置兜底”的顺序选择能力匹配的模型。

```text
配置页面 -> 加密数据库 -> AI Gateway -> 文本 / 视觉 / 生图 / 图生图
                            ^
                       环境变量兜底
```

## 4. 模块设计

- 配置中心：供应商预设自动填充默认地址和常用模型；仍可人工修改。
- 配置验证：用户点击“测试连接”，网关以该配置发起最小请求；文本验证文本调用，视觉验证视觉调用，生图与图生图验证接口可达性，不产生成本图片。
- 配置维护：允许编辑名称、地址、模型、能力、启用状态及可选的新 Key；删除仅删除当前用户自己的配置。
- AI Gateway：统一能力选择。用户配置位于列表首位，缺少能力时才降级到系统默认。

## 5. 权限和安全

仅已登录成员可读取和维护自己的配置。API Key 不进入浏览器状态、响应、日志、异常文本或 Git。连接测试不返回上游响应正文，仅返回成功状态和本次验证的能力。

## 6. 错误处理和验收

- 缺少某能力模型时，显示明确的“前往 AI 模型配置”错误。
- 配置测试失败显示上游的安全摘要，不泄露 Key。
- 保存、编辑、停用和删除均只影响当前用户。
- 男装、女装、IP、封面等既有生图路径继续传入当前用户 ID，使用用户的 `image.generate`/`image.edit` 配置。

## 7. 部署影响

继续要求生产环境保留 `AI_CREDENTIAL_ENCRYPTION_KEY`，否则已有用户 Key 无法解密。服务器环境变量作为系统兜底，可在所有用户配置完成后自行移除；删除前必须验证至少一个用户配置的各项能力。

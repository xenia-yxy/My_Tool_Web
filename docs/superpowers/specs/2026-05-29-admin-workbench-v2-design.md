# AI Practice 管理端 v2 设计方案

记录日期：2026-05-29

## 1. 设计目标

把当前 `/admin` 从“内容列表 + Markdown 编辑器”升级为一个轻量业务操作台雏形。

本阶段的目标不是做完整企业后台，而是给个人 AI Practice 站点建立可长期扩展的后台骨架：

```text
公开端负责建立信任和转化。
管理端负责沉淀内容、服务、工具和业务线索。
后续用户端和小程序端可以接入同一套内容与业务资产。
```

后台第一版应该有产品感，但不能变成空壳系统。真实做实的部分是“内容资产中心”，其他业务模块只建立入口和边界。

## 2. 范围判断

当前项目仍然采用单体 Next.js App Router：

- 公开端在 `src/app/(public)`。
- 管理端在 `src/app/admin`。
- Auth API 在 `src/app/api/auth`。
- 服务端内容逻辑在 `src/server/content-*`。
- 数据模型目前只有 `User` 和 `Note` 作为核心业务模型。

本阶段不拆成独立 admin 项目。公开端和管理端继续在一个代码库、一个 Next.js 应用中维护，通过路由和鉴权边界区分。

## 3. 后台信息架构

后台侧边栏使用统一结构：

```text
仪表盘
内容资产
工具管理
用户管理
权限管理
订单管理
数据大屏
系统设置
```

本阶段做实：

- `仪表盘`
- `内容资产`

本阶段只占位：

- `工具管理`
- `用户管理`
- `权限管理`
- `订单管理`
- `数据大屏`
- `系统设置`

占位页需要表达“该模块已进入后台结构，但当前阶段暂未启用”，并给出后续用途，不做假数据、不做不可用表单。

## 4. 管理端布局

管理端继续使用独立的 `/admin` 视觉框架，但风格要和公开端统一：

- 浅色背景。
- 深蓝灰文字。
- 冷蓝作为少量强调色。
- 避免大面积蓝色、紫色或渐变。
- 卡片边角保持克制，不做过度圆角。
- 左侧侧边栏用于主导航。
- 主内容区顶部显示当前模块标题、说明和关键操作。

桌面端布局：

```text
左侧固定导航 + 右侧内容工作区
```

移动端布局：

```text
顶部品牌区 + 横向或换行模块导航 + 内容工作区
```

不能出现横向滚动，导航文字不能挤压重叠。

## 5. 仪表盘设计

仪表盘是后台默认首页，用于快速判断当前内容运营状态。

首版展示：

- 内容总数。
- 已发布数量。
- 草稿数量。
- 最近更新内容。
- 快速新建内容入口。
- 进入内容资产中心入口。

仪表盘不做复杂商业数据，不展示订单金额、用户增长、转化率等暂时没有真实来源的数据。

## 6. 内容资产中心

内容资产中心继续承接当前内容发布闭环，但要从“简单列表”升级成“可持续写作和发布的工作台”。

列表能力：

- 显示所有内容资产。
- 支持状态筛选：全部、草稿、已发布。
- 支持关键词搜索：标题、摘要、slug。
- 显示内容统计：总数、草稿数、已发布数。
- 显示更新时间和发布时间。
- 提供编辑、发布、撤回、删除操作。

编辑能力：

- 标题。
- slug。
- 摘要。
- Markdown 正文。
- 保存草稿。
- 发布。
- 撤回。
- 返回列表。

编辑体验增强：

- Markdown 编辑区保持大尺寸。
- 增加预览能力，优先使用同页分栏或编辑 / 预览切换。
- 预览使用和公开知识详情页接近的排版风格。
- 先不做自动保存，避免在当前 Server Action 表单模式下引入复杂状态。

## 7. 数据和服务边界

本阶段优先复用现有 `Note` 模型，不做数据库大改。

可以在服务层增加查询组合：

- 内容统计查询。
- 最近更新内容查询。
- 带搜索和状态筛选的列表查询。

如果后续需要扩展“内容类型”，再考虑把 `Note` 演进为更通用的 `ContentAsset`，或增加 `type`、`tags`、`cover` 等字段。本阶段先不引入这些字段，避免迁移成本超过真实需求。

## 8. 权限和安全

所有 `/admin` 页面继续要求管理员登录。

本阶段不做多角色权限系统，但后台结构里保留 `权限管理` 入口作为未来边界。

内容操作继续通过服务端动作完成，并在每个动作中校验管理员身份。

## 9. 错误处理

表单校验继续在服务端完成：

- 标题不能为空。
- 正文不能为空。
- slug 需要被规范化。

后续可以加 toast 或表单内错误提示。本阶段如果实现成本不高，可以保留现有 redirect 流程；不要为了错误展示引入复杂客户端状态。

删除操作需要保留确认，避免误删内容资产。

## 10. 测试策略

单元测试优先覆盖服务层：

- 内容搜索过滤。
- 内容统计计算。
- slug 和输入规范化。
- 发布、撤回状态解析。

页面级测试暂不引入浏览器自动化，先通过 `pnpm test`、`pnpm lint`、`pnpm build` 验证。

## 11. 本次不做范围

- 不做小程序端。
- 不做真实用户端会员中心。
- 不做多租户。
- 不做订单支付。
- 不做真实数据大屏。
- 不做完整 RBAC 权限系统。
- 不做工具运行平台。
- 不做内容版本历史。
- 不做自动保存。
- 不做 SaaS 化拆分。

## 12. 验收标准

- `/admin` 进入后是仪表盘，不再只是内容列表。
- 管理端有统一侧边栏，并包含未来模块入口。
- 未启用模块有清晰占位页，不出现假功能。
- 内容资产中心支持状态筛选和关键词搜索。
- 内容资产中心能看到总数、草稿数、已发布数。
- 内容编辑页支持 Markdown 预览。
- 发布、撤回、删除、保存草稿的现有闭环不退化。
- 管理端视觉风格和公开端保持克制统一。
- 所有后台页面仍然受管理员登录保护。
- `pnpm test`、`pnpm lint`、`pnpm build` 通过。

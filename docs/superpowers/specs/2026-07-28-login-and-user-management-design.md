# 技术方案：登录流程与账户管理

## 1. 背景和目标

网站应先展示公开首页，访问者主动点击登录后在首页弹框认证。登录成功后进入工具工作台或回到原始受保护页面。管理员需要能在网站内维护登录用户，不再依赖修改服务器环境变量和重新部署。

## 2. 范围和不做事项

实现首页登录弹框、可靠回跳、管理员用户管理、账号创建、密码重置、账号启停和即时失效。不会开放公开注册、邮箱验证码、忘记密码邮件或第三方 OAuth。

## 3. 角色和权限

- `ADMIN`：可使用全部工具、管理用户、维护自己的模型配置。
- `USER`：可使用工具和维护自己的模型配置，不能查看或管理其他用户。
- 新建账户默认 `USER`；现有管理员角色不改变。

## 4. 登录流程

```text
首页 -> 点击登录 -> 首页登录弹框 -> Credentials 登录
  -> 有安全 callbackUrl：跳回原受保护页面
  -> 无 callbackUrl：进入 /tools

受保护页面 -> 未登录 -> /?login=1&callbackUrl=<原页面>
  -> 首页自动打开同一登录弹框
```

登录弹框支持关闭、Esc、遮罩点击关闭，并在关闭时移除 `login=1`，避免刷新后重复弹出。回跳地址继续只允许站内相对路径。

## 5. 用户管理

管理员在 `/account/users` 查看用户列表。每条用户包含账号、邮箱、角色、创建时间、最近登录、状态和操作：创建、编辑账号信息、重置密码、停用/启用。禁止管理员停用或降级最后一个管理员，禁止删除账户以保留审计和用户资产。

## 6. 会话和安全

保留已有密码哈希、失败锁定和登录审计。用户被停用或密码被管理员重置后，受保护页面/API 的会话检查将拒绝旧 JWT。用户凭据永不在列表或日志返回。管理员操作写入既有登录审计外的用户更新时间和状态。

## 7. 数据库设计

现有 `User` 已有 `role`、`disabledAt`、`passwordChangedAt`、失败锁定和登录时间字段。本期将默认角色改为 `USER`，并新增 `authVersion Int @default(1)`：创建时写入 JWT，密码重置/停用时递增，使旧会话不能继续通过服务端校验。

## 8. 接口设计

- `GET /api/account/users`：管理员获取脱敏用户列表。
- `POST /api/account/users`：管理员创建普通用户。
- `PATCH /api/account/users/[id]`：管理员更新用户资料、角色、密码或状态。

所有接口要求 `ADMIN`，并验证目标用户、账号唯一性、密码长度和最后管理员保护。

## 9. 测试与部署

测试覆盖：默认角色、回跳安全性、管理员授权、创建/重置/禁用规则和会话版本失效。部署包含 Prisma 加法迁移；上线前备份生产数据库，离线 Docker 包不包含 `.env.production` 或任何真实 Key。回滚使用上一镜像，数据库的加法字段保留，不执行重置或删库。

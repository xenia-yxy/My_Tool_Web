# 功能开发文档：系列视频分析工具

## 1. 背景和目标

当前账号正在做“挑战 100 个自媒体赛道”的系列化视频，需要一个通用工具，把单条视频数据、视频链接、赛道信息和系列进度结构化输入，并输出可执行的诊断和下一步建议。

第一版目标是新增一个稳定可用的工具页，帮助用户分析系列化视频是否值得继续、问题出在哪里、下一条应该怎么改。核心分析使用本地规则，不依赖外部平台抓取或 AI 接口，避免抖音、小红书、B站等链接解析不稳定影响主流程。

## 2. 已确认需求

- 新增“系列视频分析”功能，用于分析和建议系列化短视频。
- 支持粘贴视频链接，至少能记录链接并识别常见平台。
- 支持手动输入视频基础信息和数据指标。
- 支持链接加手动数据的混合输入。
- 输出对标题、开头、内容结构、人设、赛道继续价值和下一条内容方向的建议。
- 功能要通用，不绑定单个平台或单个赛道。
- 第一版优先保证可用、可测试、可复用。

## 3. 本次不做

- 不做真实平台数据抓取。
- 不做登录第三方平台或调用抖音、小红书、B站私有接口。
- 不做长期历史记录和数据库存储。
- 不做 AI 接口生成建议。
- 不做多账号权限和团队协作。
- 不做自动发布、定时发布或平台运营自动化。

## 4. 用户流程

1. 用户进入 `/tools/series-video-analyzer`。
2. 用户填写视频链接、平台、赛道、系列期数、标题、内容简述等基础信息。
3. 用户填写播放、点赞、评论、收藏、转发、涨粉、完播率、平均观看时长等数据。
4. 用户点击或即时看到分析结果。
5. 系统输出整体评级、问题诊断、关键数据解释、赛道建议和下一条视频建议。
6. 用户复制分析报告，用于后续复盘或继续和 Codex 沟通。

## 5. 前端范围

新增页面：

- `src/app/tools/series-video-analyzer/page.tsx`

新增组件：

- `src/components/tools/series-video-analyzer.tsx`

更新导航：

- 在 `src/components/tools/nav-config.ts` 的“创作”分组增加入口。

页面区域：

- 视频输入区：平台、链接、账号类型、赛道、系列期数、标题、发布时间、视频时长、内容简述。
- 数据输入区：播放、点赞、评论、收藏、转发、涨粉、完播率、平均观看时长。
- 分析结果区：整体评级、主要诊断、数据洞察。
- 下一步建议区：下一条方向、标题候选、封面文案、评论区引导、是否继续当前赛道。

## 6. UI/UX 要求

- 采用现有工具页风格：白底、浅边框、8px 以内圆角、密集但清晰的信息布局。
- 不做营销落地页，进入页面即是可用工具。
- 表单和结果并列或上下排列，桌面端优先提高扫描效率，移动端自然堆叠。
- 数字输入要允许空值，空值不阻断基础分析。
- 链接识别失败时不报错，只给出温和提示。
- 结果文案要直接、可执行，避免泛泛鼓励。
- 提供“复制分析报告”按钮。

## 7. 后端范围

第一版不新增后端接口。

分析逻辑放在纯函数模块：

- `src/lib/series-video-analyzer.ts`

该模块负责：

- 平台链接识别。
- 数据指标归一化。
- 互动率、收藏率、评论率、涨粉率等派生指标计算。
- 根据规则生成诊断和建议。
- 生成可复制的文本报告。

## 8. 数据和存储

第一版不落库，不新增 Prisma 模型或 migration。

前端状态只保存在当前页面生命周期内。后续如果需要保存历史记录，可以再扩展：

- `SeriesVideoProject`
- `SeriesVideoEntry`
- `SeriesVideoAnalysisSnapshot`

## 9. 业务规则

平台识别：

- 包含 `douyin.com` 或 `v.douyin.com`：识别为抖音。
- 包含 `xiaohongshu.com` 或 `xhslink.com`：识别为小红书。
- 包含 `bilibili.com` 或 `b23.tv`：识别为 B站。
- 其他链接：识别为其他平台。

数据诊断规则：

- 播放高但涨粉低：人设或系列承接弱。
- 播放低但收藏高：内容有价值，标题封面或开头弱。
- 评论高但收藏低：情绪或争议强，信息沉淀不足。
- 收藏高但评论低：有用但互动设计弱。
- 完播率低：开头或中段结构需要重做。
- 涨粉率高：系列方向值得继续。
- 数据整体弱但评论反馈具体：可优化后重测。
- 数据整体弱且反馈弱：建议换切入角度或暂停该赛道。

输出建议应覆盖：

- 标题/封面。
- 开头 3 秒。
- 中段结构。
- 人设表达。
- 赛道继续/重测/暂停判断。
- 下一条视频方向。

## 10. 异常和边界情况

- 所有数据为空：输出基础模板建议，不做强诊断。
- 只有链接无数据：识别平台，提示补充数据后可分析。
- 指标为负数：前端限制为非负数，逻辑层按 0 处理。
- 完播率超过 100：逻辑层按 100 处理。
- 播放量为 0 但有互动：按异常数据处理，提示核对。
- 标题为空：建议补充标题，并给出通用标题框架。
- 赛道为空：以“当前赛道”占位，不阻断报告生成。

## 11. 验收标准

### 功能验收

- [ ] 用户可以进入 `/tools/series-video-analyzer`。
- [ ] 用户可以填写链接和视频数据。
- [ ] 系统可以识别抖音、小红书、B站和其他平台链接。
- [ ] 系统可以基于输入生成诊断和建议。
- [ ] 系统可以生成可复制的分析报告。

### 前端验收

- [ ] 页面出现在工具台创作导航中。
- [ ] 表单在桌面端和移动端均可正常使用。
- [ ] 空数据、部分数据和完整数据都有合理结果。
- [ ] 按钮、输入框、结果卡片不出现文字溢出或布局错位。

### 后端验收

- [ ] 第一版不新增后端接口。
- [ ] 不新增数据库 migration。
- [ ] 分析逻辑通过纯函数单元测试覆盖。

### UI/UX 验收

- [ ] 结果文案清晰区分“数据解读”和“下一步行动”。
- [ ] 不使用过度装饰或营销型页面结构。
- [ ] 复制报告操作有明确反馈。

### 异常情况验收

- [ ] 只输入链接时不会报错。
- [ ] 输入异常数字时不会导致 NaN 展示。
- [ ] 无法识别的平台链接仍能保存为“其他平台”。

## 12. 测试建议

新增测试：

- `tests/series-video-analyzer.test.ts`

测试覆盖：

- 平台链接识别。
- 派生指标计算。
- 低完播诊断。
- 高播放低涨粉诊断。
- 高收藏低播放诊断。
- 空输入报告。
- 异常数字归一化。

## 13. 开发边界

第一版应保持小而完整：

- 新增一个页面。
- 新增一个组件。
- 新增一个纯逻辑模块。
- 新增一个测试文件。
- 更新工具导航。

不改动登录、权限、数据库、AI 网关、图片生成、电商工具等现有模块。

## 14. PR 和上线影响

- 无数据库变更。
- 无环境变量变更。
- 无第三方 API 依赖。
- 无部署脚本变更。
- 回滚方式简单：移除新增页面、组件、逻辑模块、测试和导航入口。

## 设计自检

- 无待确认项阻塞第一版实现。
- 链接解析边界明确：第一版只识别平台和记录链接，不承诺抓取平台数据。
- 历史保存明确后置，避免第一版引入数据库复杂度。
- 分析规则先用可测试纯函数实现，后续可替换或叠加 AI 建议。

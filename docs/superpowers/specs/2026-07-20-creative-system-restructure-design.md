# 创作系统重构设计

## 目标

将当前分散、重复且状态不可靠的工具页面重构为可持续使用的创作系统。系统必须保证上传图片、素材选择、模特、提示词、生成任务、结果画廊和历史记录形成闭环；离开页面后任务和结果不丢失。

## 已确认的信息架构

顶级导航只保留四个分组：

1. 内容创作：IP 创作、IP 衍生、平台封面、自由生图。
2. 电商视觉：男装工作台、女装工作台、零食百货工作台。
3. 资产：选品中心、素材中心、模特库、任务与结果。
4. 辅助：创作画布、热点/计划、视频分析。

外部网站导航、重复的穿搭提示词入口、重复的 AI 穿搭入口、没有完整输入输出闭环的半成品页面不再出现在主导航。

男装、女装、零食百货为独立业务工作台。它们的页面、预设、提示词、可选素材和默认画面控制分开，底层复用同一套素材、任务、画廊和存储能力。

## 核心数据关系

```text
选品中心 -> 商品档案和多张商品图
素材中心 -> 单张可复用图片（商品、脸部、身体、动作、背景、构图、风格）
模特库 -> 脸部/身体素材的组合档案，以及生成的模特图
创作工作台 -> 输入快照、最终提示词、参考图角色、画面参数
任务中心 -> 队列状态、进度、失败原因、重试、取消
结果画廊 -> 生成图片、来源任务、提示词、参考图角色、加入素材/再次创作
```

选品中心与素材中心独立。选品图片不会自动复制到素材中心；用户可在选品详情主动复制。素材中心为公开库，所有工具都可选择其中的素材。

## 素材与模特

素材中心必须按七类显示和筛选：商品、脸部、身体、动作、背景、构图、风格。上传时用户只选择业务用途；不暴露保真度、策略等工程参数。

每个上传控件统一支持本地上传与从素材中心选择。上传/选择后立即显示预览、用途标签、大图预览、替换和删除。

模特库独立于素材中心。模特档案可由脸部/身体素材创建或系统生成；模特卡片必须显示真实脸部/身体图片。男装和女装从同一模特库引用，但默认按性别/用途筛选。

历史恢复的数据需要明确标记为“待分类素材”。恢复时不能把所有图片固定归类为 `other`，也不能假定恢复文件可还原模特档案；无原始数据库时必须提供重新分类与新建模特档案的路径。

## 三个电商工作台

每个工作台独立，但采用同一个四步框架：

1. 选择成果类型。
2. 选择素材。
3. 设置画面。
4. 确认最终提示词并生成。

男装和女装保留：商品主图/场景图、单品上身穿搭、一衣多搭、平铺多搭拆分、参考图复刻。零食百货保留：商品主图/详情图、使用场景、平台种草图、参考图风格复刻，不显示模特或穿搭参数。

页面默认最多显示五个画面选项。人物、脸部、动作、身材、构图、背景、比例只在当前成果类型需要时出现。高级画面控制默认折叠。

参考图必须使用明确用途标签：商品、脸部、身体、动作、背景、构图、风格。商品保留、构图保持、背景保持、背景变化、动作随机等使用业务开关表达，不使用“锁定策略”和“保真百分比”等工程术语。

## 内容创作

内容创作保留四个入口：

1. IP 创作：用文字或参考图生成 IP 主形象，保存为 IP 档案。
2. IP 衍生：基于一个 IP 档案生成换装、动作场景、表情包、配饰和系列内容。主 IP 决定身份和画风；服装参考只迁移服装信息。
3. 平台封面：按小红书、抖音、闲鱼、电商预设生成封面候选与文案建议。
4. 自由生图：一句描述、可选参考图、比例和补充要求，默认生成一张。

IP 创作和 IP 衍生必须分开。IP 衍生只从已保存 IP 档案开始，不能在同一复杂表单中混合创建 IP 与编辑 IP。

创作画布保留为高级功能，不是普通创作的必经步骤。Skill 管理只在画布的高级设置中出现。

## 提示词与历史

每个生成页面的最终提示词默认可见，并可直接编辑。编辑后的提示词必须进入实际生成请求，而不只是保存一条工作记录。

每次提交生成时保存完整输入快照、最终提示词、参考图 URL 与用途、任务 ID 和结果 ID。工具历史按具体功能隔离，不能让男装子功能因为路径匹配顺序而共用错误的历史。

## 任务、结果与可靠性

生成按钮只负责创建任务并入队。任务中心提供排队、生成中、成功、失败、重试和取消状态；结果在当前页面任务抽屉显示，完成后进入画廊。

模型调用必须有请求超时、任务心跳、最大执行时长和可恢复失败状态。超时任务必须自动标记失败或重试，不能永久停留在 `RUNNING`。

页面缓存只能作为短暂界面恢复，服务端任务状态是唯一事实来源。

## 存储与发布

运行时图片应优先上传 OSS，数据库保存 OSS 公网 URL。应用不能先永久写入本地运行目录再上传 OSS；临时文件必须在上传后删除。

生产环境必须在发布前验证 OSS bucket、endpoint、public base URL 和访问权限。未配置 OSS 时，界面和日志必须明确告知本地存储模式与磁盘风险。

发布版本必须记录 Git commit、Docker image tag、数据库迁移版本和烟雾测试结果。远端运行镜像必须与本地已提交版本对应。

## 分期实施与验收

### 第一期：稳定底座

修复素材分类、模特档案恢复/创建、图片 URL 检查、生成队列超时和失败恢复、真实提示词提交、功能历史隔离、OSS 预检与本地磁盘清理策略。

验收：素材、脸部与模特图可显示并能被选择；任务不会无限生成中；改过的提示词影响请求；结果和历史可恢复；生产发布可追溯。

### 第二期：电商工作台

将男装、女装、零食百货重组为独立工作台与四步工作流。删除或重定向旧的重复入口。

验收：每个工作台只显示自身需要的选项；完整流程可从素材/选品到生成结果闭环；上传、素材选择、人物与参考图交互一致。

### 第三期：内容创作与高级功能

实现 IP 创作到 IP 档案到 IP 衍生的闭环，重做平台封面与自由生图，画布和 Skill 下沉为高级流程。

验收：IP 可创建、保存、选择并进行衍生；封面图有平台预设与可编辑提示词；画布不干扰普通创作。

## 不在本次主路径中

外部网站导航和无真实数据源的页面不作为核心产品功能开发。它们将在导航中隐藏或在后续确认真实数据源后重做。

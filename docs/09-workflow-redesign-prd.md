# 工具台工作流重新设计 PRD

## 0. 项目信息

| 项 | 内容 |
| --- | --- |
| 项目名称 | xenia_workflow_redesign |
| 技术栈 | Next.js App Router + TypeScript + Tailwind CSS + Prisma + PostgreSQL + Auth.js |
| 当前阶段 | MVP 内容发布后台 → 工具台体验升级 |
| 原始需求 | 重新设计工具台，引入引导式工作流，理清工具分组与 admin-frontend 关系 |

### 原始需求复述

当前工具台有 10 个工具平铺在侧边栏，无分组、无串联、有重复。用户不知道"先做什么后做什么"，总览页仅展示静态卡片。本次重新设计要解决：工具分组、引导式工作流、重复工具合并、总览页升级、遗留页面清理，以及明确 admin-frontend 与主项目的关系（本次不改其代码）。

---

## 1. 产品目标

### 1.1 核心目标

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| G1 | 建立工具分组与导航层级 | 将 10 个平铺工具重组为 3-4 个功能分组，降低查找成本 |
| G2 | 引入引导式工作流 | 定义"规划→创作→生成→发布"四阶段路径，让用户知道下一步做什么 |
| G3 | 消除重复与遗留 | 合并服装类三页为一页，废弃 directory 旧版，归位模型配置 |

### 1.2 成功标准

- 工具导航从"10 个平铺项"变为"4 组分类 + 组内工具"，层级 ≤ 2 级。
- 总览页能展示今日任务数、最近生图、未发布草稿等工作流状态摘要。
- 总览页提供"当前阶段 + 下一步建议"引导，用户可一键跳转到推荐工具。
- 服装类工具从 3 个页面合并为 1 个页面（Tab 切换），功能不丢失。
- directory 旧版页面不再出现在导航中，访问时重定向到网站库。
- 模型配置不再出现在工具导航中，归位至设置区。

## 3. 工具分组方案

### 3.1 分组原则

按**工作流阶段**分组，而非按技术类型分组。用户的心智模型是"我要完成一件事"，分组应贴合工作流程。

### 3.2 分组结果

| 分组 | 对应工作流阶段 | 包含工具 | 说明 |
| --- | --- | --- | --- |
| 规划 | 规划阶段 | 计划中心（plan） | 每日/每周计划、四象限管理 |
| 创作 | 创作 + 生成阶段 | AI 自定义生图（ai-image）、IP 原型工坊（ip-prototype） | 视觉素材生成与 IP 形象构思 |
| 电商 | 创作阶段（电商场景） | 服装起号（合并后）、零食百货起号（snack-grocery） | 电商起号提示词工具集 |
| 资源 | 全阶段辅助 | 网站库（sites） | 书签管理，跨阶段使用 |

### 3.3 导航层级设计

```
/tools（总览 — 工作流仪表盘）
│
├── 规划
│   └── 计划中心          /tools/plan
│
├── 创作
│   ├── AI 生图           /tools/ai-image
│   └── IP 原型工坊       /tools/ip-prototype
│
├── 电商
│   ├── 服装起号          /tools/fashion-prompts  （合并 menswear + womenswear + outfit-image）
│   └── 零食百货起号      /tools/snack-grocery
│
└── 资源
    └── 网站库            /tools/sites
```

### 3.4 导航调整清单

| 操作 | 对象 | 动作 |
| --- | --- | --- |
| 分组 | plan / ai-image / ip-prototype / snack-grocery / sites | 归入对应分组 |
| 合并 | menswear + womenswear + outfit-image → fashion-prompts | 三合一 |
| 废弃 | directory | 从导航移除，路由重定向至 sites |
| 归位 | models（原 /account/models） | 从工具导航移除，保留在 /account/settings 或移至 /tools/settings |

侧边栏从平铺 10 项变为 4 组折叠菜单，默认展开当前所在组。

## 4. 引导式工作流设计（核心）

### 4.1 工作流阶段定义

```
┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│  规划   │ ──▶ │  创作   │ ──▶ │  生成   │ ──▶ │  发布   │
│  Plan   │     │ Create  │     │ Generate│     │ Publish │
└─────────┘     └─────────┘     └─────────┘     └─────────┘
   计划中心        电商起号         AI 生图         写文章
                   IP 原型          IP 原型         发布知识库
```

| 阶段 | 目的 | 使用工具 | 产出物 |
| --- | --- | --- | --- |
| 规划 | 确定今天/本周要创作什么内容 | 计划中心 | 每日任务、四象限优先级 |
| 创作 | 构思内容方向、生成文案提示词 | 服装起号 / 零食百货起号 / IP 原型工坊 | 提示词文案、IP 原型方向 |
| 生成 | 生成视觉素材 | AI 自定义生图 / IP 原型工坊 | AI 图片、IP 生成图 |
| 发布 | 整理成果为文章并发布 | 写文章（Note 编辑）→ 发布 | 知识库公开文章 |

### 4.2 工具串联设计

串联分为两个层次：**UI 引导链接**（P0，本次必做）和**数据关联**（P1，后续增强）。

#### 4.2.1 UI 引导链接（P0）

在各工具页面底部或操作完成后，提供"下一步"引导按钮：

| 当前工具 | 完成操作后 | 下一步引导 |
| --- | --- | --- |
| 计划中心 | 创建/完成任务 | "去生成素材 →" 跳转 AI 生图 |
| 服装起号 / 零食百货起号 | 生成提示词 | "去 AI 生图 →" 跳转 AI 生图 |
| AI 生图 | 生成图片成功 | "写文章发布 →" 跳转 Note 编辑器 |
| IP 原型工坊 | 生成原型 | "去 AI 生图 →" 或 "写文章发布 →" |
| Note 编辑器 | 保存草稿 | "发布到知识库 →" |

#### 4.2.2 数据关联（P1，后续增强）

- 计划任务可关联生成的 AI 图片记录（AiImageAsset）。
- 计划任务可关联最终发布的 Note。
- 总览页可展示"任务 → 素材 → 文章"的完整链路。

> 本次 P0 仅做 UI 引导链接，数据关联列入 P1。

### 4.3 总览页工作流引导

总览页（/tools）顶部展示**工作流进度条**，反映当前状态：

```
规划 ──● 创作 ──○ 生成 ──○ 发布
 ✓      进行中
```

- **规划**：今日有 N 个任务，已完成 M 个
- **创作**：检测到最近使用了提示词工具
- **生成**：今日生成 K 张图
- **发布**：未发布草稿 J 篇

根据状态自动推荐下一步操作，如："你今天有 2 个待办任务未完成，去计划中心 →"。

## 5. 总览页重新设计

### 5.1 页面布局

```
┌──────────────────────────────────────────────────────────┐
│                    工作流引导区域（顶部）                    │
│  [规划 ●] ── [创作 ○] ── [生成 ○] ── [发布 ○]              │
│  当前阶段：创作 | 下一步建议：去 AI 生图生成素材  [前往 →]   │
├──────────────────────────────────────────────────────────┤
│                    状态摘要区域（中部）                     │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ 今日任务  │  │ 未发布   │  │ 今日生图  │  │ IP 原型   │  │
│  │   3/5    │  │  2 篇    │  │   4 张   │  │  2 个项目 │  │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘  │
│                                                          │
│  最近生图（缩略图 × 4）               最近草稿（列表 × 3）   │
├──────────────────────────────────────────────────────────┤
│                    快速操作区域（底部）                     │
│  [+ 新建计划]  [⚡ 快速生图]  [✏ 写文章]  [🔖 看书签]      │
└──────────────────────────────────────────────────────────┘
```

### 5.2 区域说明

#### A. 工作流引导区域

| 元素 | 内容 | 数据来源 |
| --- | --- | --- |
| 阶段进度条 | 规划→创作→生成→发布 四节点 | 综合计算 |
| 当前阶段 | 高亮当前所处阶段 | 基于今日活动推断 |
| 下一步建议 | 文字描述 + 跳转按钮 | 根据阶段状态推荐 |

下一步建议逻辑：

| 条件 | 建议 |
| --- | --- |
| 今日有待办任务未完成 | "去计划中心完成任务 →" |
| 任务已完成但今日未生图 | "去 AI 生图生成素材 →" |
| 今日已生图但有未发布草稿 | "去发布草稿到知识库 →" |
| 今日无任务 | "新建今日计划 →" |

#### B. 状态摘要区域

| 卡片 | 展示内容 | 数据来源 |
| --- | --- | --- |
| 今日任务 | 已完成/总数（如 3/5） | DailyPlanItem（今日） |
| 未发布草稿 | 草稿数量 | Note（status=PRIVATE） |
| 今日生图 | 今日生成图片数 | AiImageAsset（今日） |
| IP 原型 | 进行中的项目数 | IpPrototypeProject |

附加展示：
- **最近生图**：最近 4 张 AI 生图缩略图，点击进入详情。
- **最近草稿**：最近 3 篇未发布 Note 标题 + 更新时间，点击进入编辑。

#### C. 快速操作区域

| 按钮 | 动作 |
| --- | --- |
| 新建计划 | 跳转 /tools/plan，聚焦新建输入 |
| 快速生图 | 跳转 /tools/ai-image |
| 写文章 | 跳转 Note 编辑器（新建） |
| 看书签 | 跳转 /tools/sites |

## 7. admin-frontend 关系分析

### 7.1 当前关系说明

| 项 | 主项目 /admin | admin-frontend |
| --- | --- | --- |
| 技术栈 | Next.js App Router（SSR） | Vite + React（纯前端 SPA） |
| 运行端口 | 主项目端口（默认 3000） | 独立端口 3002 |
| 认证方式 | Auth.js Session | Bearer Token 调主项目 API |
| 定位 | 主项目内置后台 | 独立管理面板（Vite 版替代） |
| 本次动作 | 保持现状 | 不改代码 |

### 7.2 功能重叠分析

| 功能 | 主项目 /admin | admin-frontend | 重叠程度 |
| --- | --- | --- | --- |
| 仪表盘 | ✗（无） | ✓ | admin-frontend 独有 |
| 内容列表 | ✓ Note CRUD | ✓ 内容资产列表 | 高度重叠 |
| 内容编辑 | ✓ Note 编辑 | ✓ 内容编辑表单 | 高度重叠 |
| 发布/撤回 | ✓ | ✓ | 完全重叠 |
| 工具台管理 | ✓（/tools 全部） | ✗ | 主项目独有 |
| 知识库管理 | ✓ | ✗ | 主项目独有 |

**结论**：admin-frontend 本质是主项目 admin 功能的 Vite 版本替代，两者在内容管理上完全重叠。admin-frontend 额外有仪表盘功能，但缺少工具台和知识库管理。

### 7.3 未来整合建议（本次不实施）

| 阶段 | 建议 |
| --- | --- |
| 短期（本次） | 不改 admin-frontend 代码。在文档中明确两者定位：admin-frontend 专注内容编辑体验优化，主项目 /admin 作为全功能后台。 |
| 中期 | 将 admin-frontend 的仪表盘能力迁移到主项目 /admin，使主项目成为单一管理入口。 |
| 长期 | 废弃 admin-frontend，统一到主项目 Next.js 架构，消除双端维护成本。 |

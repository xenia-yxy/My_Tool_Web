# UI 开发通用规则

用途：每次开发新页面或新功能时使用，防止 UI 跑偏。

---

## 1. UI 设计必须先回答

```text
这个页面的主任务是什么？
谁在用？
用户为什么进入这个页面？
用户完成任务后得到什么结果？
页面上哪些是 P0 / P1 / P2？
哪些操作是主要操作？
哪些操作是危险操作？
哪些状态必须出现？
```

不回答这些，不直接开始画页面或写代码。

---

## 2. 信息优先级

```text
P0：完成主任务必须看到的信息和操作。
P1：辅助判断的信息。
P2：低频、管理、导出、高级筛选、批量配置等能力。
```

规则：

```text
P0 必须优先显示。
P1 可以次级展示。
P2 不要抢占主任务，可以折叠、后置或放到更多操作。
```

---

## 3. 企业后台默认规则

```text
使用企业后台密度。
使用稳定的 8px 间距体系。
主按钮只保留一个。
危险操作使用 danger token。
危险操作需要二次确认。
筛选区不要挤压表格主内容。
行内操作不超过 2 个，更多操作放入菜单。
详情优先用抽屉或详情页承载。
```

---

## 4. UI 不能做的事

```text
不要为了好看改变业务主流程。
不要把所有功能都放首屏。
不要卡片套卡片。
不要一个页面多个主按钮。
不要无权限时直接隐藏关键操作。
不要只做 happy path。
不要用随机颜色、随机圆角、随机阴影。
不要脱离组件库自造基础组件。
```

---

## 5. 页面验收

```text
主任务是否明确？
P0 是否优先？
主按钮是否唯一？
危险操作是否二次确认？
loading / empty / error / submitting / success / permissionDenied 是否完整？
组件库是否统一？
间距、颜色、字号是否来自规则？
是否存在 UI 跑偏或过度设计？
```
